# 预测真实历史与输入结构

请求体不变。结构门禁没有通过时仍是 HTTP 422、`HISTORICAL_DATA_ERROR`。通过结构门禁、但模型不能诚实使用时，仍是 HTTP 200、`code` 0，预测数字改为既有规则序列，不能再标成模型成功。

本说明不把外部调用方记为已全部验证。已核对的只有当前 Go 反代原样透传（不解码、不缓存）以及现有前端：规则降级已有提示，准确率和置信度为 null 时显示未知，`fallback_code` 可以被忽略。成本与健康接口不在这批。

`/info`、`/ready`、`/health`、`/models` 的字段和状态含义不因这批改变。元数据缺失时，模型信息里仍可能出现当初写进默认元数据的特征名；预测不会按那份清单运行。加载期仍用原来的固定探针向量调用 `predict`；探针宽度与元数据不一致时，模型可能在加载阶段就被拒绝。这批只约束已经加载之后的预测。

## 新增字段

预测响应增加可空字符串 `fallback_code`。没有降级时为 null。`method`、`fallback_mode`、`fallback_reason`、`model_version`、`model_accuracy` 仍在。规则降级时 `model_version`、`model_accuracy` 和每个预测点的 `confidence_level`、`confidence_lower`、`confidence_upper` 都是 null。

| 条件 | method | fallback_mode | fallback_reason | fallback_code |
| --- | --- | --- | --- | --- |
| 没有加载到模型 | `rule_based` | true | 预测模型不可用 | `MODEL_UNAVAILABLE` |
| 已加载，但输入结构无法确定 | `rule_based` | true | 模型输入结构无法确定 | `MODEL_SCHEMA_UNKNOWN` |
| 结构明确，但所需实测历史不足 | `rule_based` | true | 模型所需真实历史不足 | `MODEL_HISTORY_INSUFFICIENT` |
| 已按真实特征调用模型，但调用失败或输出不是有限数 | `rule_based` | true | 模型预测失败 | `MODEL_PREDICT_FAILED` |
| 借用模型且这次确实跑完 | `model:...` | true | 使用其他指标的模型 | `ADAPTED_MODEL` |
| 专用模型按真实特征跑完 | `model:...` | false | null | null |

同时满足多条时，上表从上到下只保留第一条。没有模型时先返回 `MODEL_UNAVAILABLE`。已加载之后，结构不明优先于历史不足，这两者都优先于模型失败；这三条都是规则降级，不用 `ADAPTED_MODEL` 掩盖。`ADAPTED_MODEL` 只表示借用模型实际执行成功，准确率仍为 null。

`MODEL_SCHEMA_UNKNOWN` 包括：元数据缺失或带 `metadata_missing`、特征清单为空、不是字符串列表、有重复或无法识别的列名、清单长度与模型或标准化器的 `n_features_in_` 不一致。这些情况不套用特征提取器、预测器或模型管理器里任何一份默认清单。三份默认清单的列和顺序本来就不一致；另外，预测器原先读取的是并不存在的 `metadata.metadata.features`，顶层 `features` 因此一直被忽略。

## 预测数字

历史不足、结构不明、模型不可用或模型失败时，输出仍是原来的规则序列，不再是用假特征喂给模型得到的数：

- 每步增长率：QPS 0.02，CPU 0.01，内存 0.005，磁盘 0.003
- 时间系数：工作日 9 点到 18 点为 1.2，0 点到 6 点为 0.6，其余为 1.0
- 第 i 步（从 1 起）为 `当前值 * (1 + 增长率 * i) * 时间系数`，QPS 截断到 0–100000，利用率截断到 0–100

结构明确且实测窗口完整时仍调用模型。滞后列改为精确时间戳后，原先用数组下标错一小时的输入会变，模型输出也可能因此改变。多步预测里，滞后和统计窗口始终锚定最新有限观测 T；只有主指标列在 `consider_historical_pattern` 为真时改用上一步预测值。

实测值为 0 时保持 0。变化率和增长率在实测基线为 0 时记为 0，不再把分母抬成 1，也不再使用 0.05、0.001 这类常数。

## 查询窗口

Prometheus 步长仍是 `1h`。查询跨度等于已声明特征相对 T 的最大小时差，至少 1 小时。结构无法确定或没有模型时只查 1 小时，用来完成原来的两点结构门禁，不按猜出来的周特征扩到 168 小时。

| 特征 | 需要的实测点 | 查询跨度 |
| --- | --- | --- |
| `*_1h_ago` | 恰好 T-1h | 1 小时 |
| `*_avg_6h`、`*_std_6h`、`*_max_6h`、`*_min_6h` | T 到 T-5h 共 6 点，不能少点再平均 | 5 小时 |
| `*_avg_24h`、`*_max_24h`、`*_growth_rate` | T 到 T-23h 共 24 点 | 23 小时 |
| `*_1d_ago` | 恰好 T-24h。24 个点只覆盖到 T-23h，仍然不够 | 24 小时 |
| `*_1w_ago` | 恰好 T-168h。168 个点只覆盖到 T-167h，仍然不够 | 168 小时 |
| 只有时间列或当前值 | 不额外要求滞后 | 1 小时 |

模型元数据没有周特征时，不会为了周滞后去查 168 小时。返回序列仍必须是有限值、单序列、严格连续的整点；空、单点、断档、缺 `value`、非有限值、多序列继续 422，不放宽。最新样本早于查询结束时间时，T 减回看可能落在窗口外，这时规则降级，不补点。

## 直接调用

`FeatureExtractor.extract_features` 与 `UnifiedPredictor.predict` 使用同一约束。提取器未收到 `required_features` 时使用它自己的清单；这份清单含周滞后，历史不够就失败，不再返回当前值的 95%、90%、85% 或常数表。点名了未知列时失败原因是“模型输入结构无法确定”。提取过程抛错时记录异常类型并抛出不含原文的预测错误，不把常数表当成成功。预测器在历史不足时不调用 `model.predict`。

内部预测缓存键的 `prediction_contract` 从 `provenance-v2` 改为 `history-schema-v3`。升级前写入的模型结果不会再被命中。
