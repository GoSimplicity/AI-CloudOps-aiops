# 知识目录刷新预算与只读预检

刷新先在线程中完成纯文件系统预检：固定可信配置根目录，枚举并读取常规单硬链接的 `.md`/`.txt` 文件，验证UTF8、文件身份和总预算。预算失败、非法编码或读故障发生时，不创建本次刷新stage，也不调用本次索引嵌入；活动generation保持原样。依赖服务自身的初始化有独立生命周期，这不是整个HTTP服务零网络初始化的承诺。

| 配置 | 默认值 | 有效范围 |
| --- | --- | --- |
| `rag.max_refresh_files` / `RAG_MAX_REFRESH_FILES` | 128 | 1..1024 |
| `rag.max_refresh_total_bytes` / `RAG_MAX_REFRESH_TOTAL_BYTES` | 33554432（32MiB） | 1..268435456（256MiB） |

环境变量优先于YAML。整数预算必须显式有效，布尔值、浮点数、空串、零或超硬上限均拒绝，不能静默回退或截断。单文件继续固定最大10MiB，与上传限制一致。受支持的空文件也计入文件数量和身份快照；字节预算按实际读取的UTF8原始字节计数，不按字符数或非空文件数估算。

目录通过scandir逐项枚举，总条目硬上限4096，包含不参与索引的其他条目；不会先把无界目录全部listdir到内存。单文件与总字节在打开前预查，在实际分块读取时再次限额，并核对打开/读取后/当前目录项的设备、inode、大小、mtime、ctime、模式和硬链接数。文件软链接、特殊文件、硬链接、文件替换及无法安全表示的文件名被拒绝。既有可信配置根软链接仍可用，但其解析目标与目录身份必须在全过程保持匹配；不跟随知识文件软链接。

文件预检完成后才创建stage并采样source revision，然后在线程中复核同一目录、完整文件清单（含空文件）和全部文件身份。这样预检期间提交的上传不能被较早文件快照覆盖。索引构建结束、发布前再次复核文件身份，最终发布仍以已有generation/revision CAS检测参与协议的并发写入。文件系统身份检查不是跨文件事务，不能声称可以阻止不参与协议的管理员在最后检查后任意改文件。

文件读取和复核不占用事件循环，其他请求与租约心跳可以继续。取消后异步调用不会续接到构建或发布，后台线程收到只读停止信号并在下一检查点结束；正在执行的系统调用不保证立即中断，但线程不持有Redis、模型或发布对象。stage已创建时仍按既有协议回收暂存资源，无法证明提交结果的版本继续保留。

本阶段限制的是目录输入文件数与字节总量，不是整个generation精确chunk数或模型费用：现有向量层仍在每次写入前限制最多1000个处理后chunk；多文件刷新总chunk数需要后续抽取共用prepare-only分块阶段准确预检。没有复制一套近似分块算法，也没有改模型manifest、FAISS、generation GC或旧固定前缀保留政策。线程读取也不代表CPU分块、模型调用或完整刷新已具备统一的总耗时/费用准入。

回归使用自有临时文件与Fake存储、嵌入边界，不访问真实模型、通知或既有Redis：

```sh
.venv/bin/pytest -q tests/unit/test_rag_refresh_snapshot_budget.py tests/unit/test_rag_refresh_atomic.py tests/unit/test_rag_ingestion.py tests/unit/test_knowledge_file_atomic.py tests/unit/test_knowledge_http_boundary.py
```
