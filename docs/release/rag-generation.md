# 知识库版本与刷新合同

知识库按活动 generation 读取。旧部署没有活动指针时，继续使用原固定前缀；首次成功发布新版本时原前缀保留。一次请求固定 generation，缓存同时绑定 generation 与 revision；读取期间版本变化会明确失败并要求重试。

刷新只接受知识目录内的常规单硬链接 `.md`/`.txt` 文件，单文件最大10 MiB，并拒绝符号链接、类型或文件身份变化；文件校验、读取及嵌入失败均保留原活动版本。新上传使用同目录私有临时文件写全并fsync后，以不覆盖的原子link发布，避免并发覆盖和刷新读取半文件。刷新先在独立前缀完整构建，随后比较活动指针和修订并以单指针 CAS 发布。并发写入导致比较失败时不覆盖已完成的写入。普通上传和删除也先复制活动快照到临时 generation 再切换；清空发布空版本。Redis 多命令事务在运行期失败不回滚，因此stage写入出错时不能把它当作已提交，而活动指针及旧版本保持不变。提交回复丢失或提交期间取消时结果未知，先核对活动版本后再操作，不得盲目重试。

**升级边界**：旧版本只理解固定前缀，也不会维护版本及并发状态；切换前必须停止旧进程的知识库读取和写入，之后才启动新版本。不能新旧进程混跑，也不能直接回退旧二进制并让它读取已切换的数据；回滚必须由部署方核对并恢复匹配的固定前缀和数据。此轮不连接或操作生产环境。

目前完整语义查询以Redis持久向量为准，查询限制15秒、最多10万个向量；单次写入最多1000个文档块，复制快照最多10万键、30秒。超出限制明确报错，不返回部分结果。扫描与复制随数据量增加而增加耗时，版本化共享索引属于后续扩展；原进程内层次检索与未纳入事务的索引整理入口当前关闭，不能宣称已具备分布式索引性能。

删除文档和清空知识库只改变活动版本；历史固定前缀永久保留供兼容恢复，其他旧generation在安全条件满足后才回收，因此这两个操作不提供物理永久擦除保证。涉及敏感信息删除时，需由数据所有者另行处理旧前缀、保留版本和备份，并设计经授权的安全擦除流程。

旧 generation 及发布结果不明的暂存版本不得按无条件TTL自动删除。版本回收必须区分活动版本、构建中、在途读写和结果未知，具备跨进程保护、崩溃恢复及审计；具体保护与回收规则以实现及对应测试为准。版本化复制会增加Redis容量需求，生产上线前需核对容量、备份与恢复方案。

本地验证使用离线 pytest 和显式隔离Redis脚本。脚本默认拒绝执行，`--execute` 仅创建带唯一标签的临时Redis并在结束后清理；需要本机已有 `redis:7.4.11-alpine` 镜像。脚本在导入业务前禁用dotenv与本机集群配置。

```sh
ENV=test PYTHON_DOTENV_DISABLED=1 PYTHONPATH=. python scripts/manual_checks/rag_refresh_redis.py --execute
```

## 版本回收与结果未知核对

读写操作以Redis服务端时间持有并续租 generation。回收在服务端原子确认版本不是active、没有有效租约且不是未知状态后，先标记删除、再分批清理；清理中断可重试。租约失效的请求会被拒绝，不能继续发布或返回部分结果。普通稳定写入会回收安全的历史代；仍在读取、构建及结果未知的版本保留。清理完成后的删除标记保留24小时以保护迟到事务，它不是数据版本TTL，不能对可能仍被读取的数据设置无条件TTL。

CAS由单条Redis `HSET` 同时写入活动版本和提交证据。提交回复丢失后，阶段标记保留为unknown。只读检查和显式审计处置使用同一管理入口，连接地址及凭据只通过受控的 `CLOUDOPS_RAG_ADMIN_REDIS_URL` 环境变量注入，不能放入命令参数或日志：

```sh
PYTHONPATH=. python scripts/manual_checks/rag_generation_admin.py --collection aiops_knowledge inspect
```

需要处置时将 `inspect` 换为 `resolve`，通过标准输入提供JSON对象，字段为 `generation`、`action`、`reason`。系统从进程真实UID确定操作者，不使用输入中自报的身份。CLI操作权限由操作系统账号和Redis权限控制，不等同于应用RBAC。

默认检查输出容量及unknown版本状态。`acknowledge` 仅适用于有原子提交证据的版本；`abandon` 仅允许没有提交证据、不是活动版本且没有有效租约的版本。两种处置都记录操作者、原因与时间；不符合条件会拒绝。不要把未知结果当作失败后自动重试，也不要在未核对时自动放弃。人工处置审计有容量上限。管理入口 `export` 接收标准输入JSON中的绝对 `path`，生成0600、不覆盖的快照并返回SHA256；导出文件及摘要必须作为持久审计副本妥善保留。人工保存和核对文件后，`archive` 接收标准输入JSON中的相同 `path` 及 `sha256`，仅归档快照中仍匹配的记录，保留导出后产生的新记录。归档需由拥有文件及Redis权限的操作者明确执行。

## HTTP 结果与已保存文件

刷新发布结果未知或已发布但缓存清理失败时，接口返回 HTTP 409、`KNOWLEDGE_REFRESH_UNCERTAIN`，包含 `published`、`outcome_unknown` 和 `retry_safe=false`。上传或新增文档的索引写入结果未知、或已写入但缓存/暂存资源清理失败时，接口返回 HTTP 409、`KNOWLEDGE_WRITE_UNCERTAIN`，同样标记 `retry_safe=false`，并返回 `file_saved=true`：文件已经写入知识目录，不能把失败理解为文件和索引都未产生副作用。操作者应先按上述管理入口核对当前版本与文件，再决定后续动作。
