# 自动修复审批持久化

自动修复审批与操作状态使用按用户隔离的 Redis 持久状态机，领取及产生副作用之前必须确认 AOF 已持久化。需要 Redis 7.2 或更新版本、持久卷、AOF、`maxmemory-policy=noeviction`，应用账号必须能够读取该策略并调用 `WAITAOF`。条件不满足或确认结果不明时拒绝执行，不退回进程内状态。运行期间不得修改淘汰策略；需监控容量并保持足够的持久存储空间。

`operation_id` 为客户端稳定 UUID，同一用户和 ID 绑定请求摘要；冲突、进行中或结果不确定时不重复执行。未提供 ID 的兼容请求仅生成待审批计划。历史、操作 ID 与计划查询均限制当前用户；过期或崩溃后的未确认状态需人工核对，禁止盲目重试。每个用户的历史索引保留最近 200 条，单次最多 50 条；防重墓碑不自动清理，容量上限为 100000，达到上限会拒绝新操作，须建立告警及可审计保留策略。

升级时停掉所有旧版本写入进程，备份并验证 Redis 持久卷后再启动新版本。旧版本进程内审批无法迁移；异步副本故障切换、清库、丢卷或恢复旧备份可能丢失防重状态，须停止写入并人工核对，不能声称已验证零丢失。CI 使用独立 Redis 验证崩溃、重启、响应丢失和跨进程竞争，没有执行生产操作。
